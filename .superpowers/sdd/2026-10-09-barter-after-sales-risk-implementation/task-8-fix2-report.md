## R1 protocol

The existing simulator stored only an operation's latest result. A higher-ranked exception could erase a previously accepted delivery whose local audited transaction had rolled back; A's original logical key then hit the monotonic-rank rejection. SUCCEEDED outbox did not query again.

Additive `20261015210000_simulated_return_event_inbox` creates `SimulatedProviderEvent`: monotonic ID, globally unique provider/event identity, operation FK, complete body, acceptance time, body/column identity check, return-kind check and UPDATE/DELETE rejection trigger. Store acceptance takes the same existing operation lock and appends the event **in the same independent provider transaction as updating current result**. A failed append or snapshot update cannot commit half acceptance. This is explicitly the nonproduction simulated provider, not a production adapter.

For accepted identities, exact complete-body comparison precedes current-rank checks. Same event/body can be delivered again without changing the provider's latest snapshot; same identity/different body rejects. New unaccepted backward progress remains rejected. Different accepted events are retained independently; append-only identity and operation lock cover overlapping callers.

`ReturnEventReconciler` is wired as a lifecycle provider in ReturnsModule, starts a one-second timer only for explicit development/test simulated configuration and signing key, and processes up to100 durable pending events per tick in acceptance order. Pending means no terminal matching IntegrationEventReceipt; there is no lease/cursor that can acknowledge a fact early. Each event goes through existing ReturnEventsService order→case locks and its atomic fact/receipt/progress/risk/audit transaction. Failure leaves the provider event available; a fresh process independently scans it. Per-event failures do not stop the remaining batch. Multiple instances may select the same row, but existing order lock/unique identity make domain changes and final audit commit once. Shutdown awaits active work; timers are unref'd. Original outbox/businessNo/provider operation remain singular, including after outbox SUCCEEDED.

No provider I/O moved inside business transactions. No domain receipt/risk/audit partial commits; no automatic owner confirmation, order restoration, refund or reservation release. Unknown/pending provider results remain unproven. Upgrade copies only the simulator's already retained latest successful return/closure facts into the inbox. It cannot reconstruct facts irretrievably overwritten by the pre-fix implementation; it does not invent them.

Harness disables automatic reconciler just as it disables existing outbox/schedulers; tests instantiate the actual reconciler explicitly. Tests use fresh instances and overlapping consumers, not fake event storage. Crash coverage injects failure immediately after durable provider acceptance and before the domain transaction, then constructs a fresh consumer; this proves that persisted handoff window, not an OS-level process-kill campaign.
