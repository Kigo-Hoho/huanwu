# 以物换物小程序 MVP 开发路线

## 技术方向

- 用户端：Taro 4 React TypeScript，首发微信小程序。
- 运营端：React TypeScript Vite Ant Design，响应式适配电脑和手机。
- 服务端：NestJS TypeScript，REST API。
- 数据库：PostgreSQL 17，Prisma ORM 7。
- 工程组织：Node.js 24 LTS 与 npm workspaces，共享类型和接口契约。
- 测试：服务端集成测试、前端组件测试和关键流程端到端测试。

选择同一套 TypeScript 技术体系，是为了让普通用户端、运营端和服务端共享订单状态、权限角色和接口类型。Taro 4 保留微信小程序规范，同时允许使用 React 组织页面；运营端采用响应式网页，第一版不单独开发管理员小程序。

## 分阶段计划

### 第一阶段 项目基础与物品审核闭环

建立多应用代码仓库、身份认证、角色权限、审计日志、物品发布、用户物品列表和运营审核。阶段结束时，普通用户可以发布并提交物品，运营人员可以在电脑或手机网页上审核，所有状态变化都有日志。

详细计划见 `2026-09-22-foundation-listing-review-implementation.md`。

### 第二阶段 投物箱与协商

实现交换提案、一物换一物、多物换一物、差价和运费协商、提案修改、接受、拒绝及物品占用检查。阶段结束时，双方可以形成结构化的交换方案，但不接入真实资金。

### 第三阶段 双向订单与履约

实现双向订单状态机、保证金和差价支付接口、双方发货、物流查询、超时任务、双方验收和结算。支付和物流均通过可替换适配器接入，测试环境使用模拟服务。

### 第四阶段 售后与风险控制

实现售后工单、证据上传、退货、差价补偿、违规账号、异常运单、举报处理和运营干预。高风险操作增加重新验证和完整审计。

### 第五阶段 试运营与质量门槛

完成端到端测试、性能与安全检查、监控告警、数据看板、隐私与交易规则、种子数据和小范围发布。试运营只开放低风险品类和单一区域。

## 阶段边界

每个阶段必须具备独立演示、自动测试和可回退提交。后一阶段只能依赖前一阶段公开的接口与数据模型，不直接读取其他模块内部实现。

第一版不加入单纯现金购买、自营回收、仓储验货、直播、复杂会员、智能估价和独立运营端小程序。这些功能根据真实交易量、双方发货完成率、纠纷率和运营成本决定是否立项。
